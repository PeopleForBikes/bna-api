# utoipa and progenitor traps when shaping the OpenAPI schemas

## Context

The specification is generated by utoipa 5.5.0, down-converted to OpenAPI 3.0 by
`@apiture/openapi-down-convert` 0.14.2 (the `generate-oas-30` recipe), and
`bnaclient` is generated from it by `cargo progenitor` (`just generate`).

## Symptom

- A field declared with `#[schema(value_type = Object, examples(...))]` loses
  its examples in the specification.
- A schema of type `[object, string, null]` converts to a 3.0 document that is
  not valid.
- An optional enum (`Option<Enum>`, rendered as `oneOf` with `null`) makes
  progenitor panic in `progenitor-impl` 0.14.0 (`to_schema.rs`), failing
  `generate-client`.

## Root Cause

utoipa ignores the examples next to `value_type`. OpenAPI 3.0 has no type
arrays, and the converter does not rewrite them. progenitor does not handle a
nullable reference.

## Solution

- Build the schema by hand with `schema_with`
  (`lambdas/src/core/resource/pipelines/schema.rs:107`).
- Express a choice of types with `oneOf`
  (`lambdas/src/core/resource/pipelines/schema.rs:86`, returning `Schema::OneOf`
  at line 103).
- Mark an optional enum `#[schema(nullable = false)]`: it becomes optional
  rather than nullable (`lambdas/src/core/resource/pipelines/schema.rs:186`,
  `lambdas/src/core/resource/cities/schema.rs:288`).

## Prevention

Run `just generate` after any schema change and read the diff of both
specifications; the `bnaclient` CI job fails on any difference.
